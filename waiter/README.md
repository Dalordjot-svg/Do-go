# COFFEEMAN Waiter

Тестовое PWA для официантов. Две вымышленные кофейни, по 12 столов, пять профилей и 45 позиций меню. Все цены тестовые.

## Запуск

Требуются Node.js 22+ и npm. Для Firebase Emulator нужен Java 21, для браузерных тестов Chromium.

```sh
cd waiter
npm ci
npm run dev -- --port 5173
```

Откройте [локальный экран установки](http://localhost:5173/). В Vite DEV кнопка «Открыть в режиме разработки» даёт доступ к первому запуску в браузере. Выберите профиль и точку, пройдите задания Саши и практический экзамен. Прогресс и сертификат сохраняются в IndexedDB.

| Раздел | Ссылка после допуска |
| --- | --- |
| Зал | [/#hall](http://localhost:5173/#hall) |
| Заказы | [/#orders](http://localhost:5173/#orders) |
| Стоп-лист | [/#stop-list](http://localhost:5173/#stop-list) |
| Чаты | [/#chats](http://localhost:5173/#chats) |

## Настоящая синхронизация через Firebase Emulator

1. Запустите `npm run emulator` в отдельном терминале. Используется проект `demo-coffeeman` и изолированные правила Emulator.
2. Скопируйте `.env.example` в `.env.local` и задайте `VITE_WAITER_EMULATOR_HOST=127.0.0.1:9000`. Перезапустите Vite.
3. Откройте приложение в двух независимых профилях Chrome. Войдите вымышленными сотрудниками одной точки.
4. Откройте стол 1 на первом клиенте. На втором должна появиться занятость и имя первого официанта. Отправьте сообщение в общий чат и проверьте получение на втором клиенте.
5. Чтобы проверить конфликт, откройте один свободный стол одновременно с обеих сторон. Для проверки остатков задайте одну порцию чизкейка, добавьте по блюду в разные заказы и подтвердите. Принятие должно произойти только в одном заказе.

Для двух физических устройств настройте `emulators.database.host` в локальной копии конфигурации на IP интерфейса тестовой сети, передайте эту конфигурацию CLI и используйте IP машины с Emulator в переменной Vite. Используйте закрытую тестовую сеть. Для установки и автономного SW с телефона нужен HTTPS с доверенным сертификатом. Проверку DEV-интерфейса можно выполнять через HTTP на адресе компьютера. Правила Emulator разрешают синтетическим профилям тестовый доступ к веткам waiter, поэтому не выставляйте порт 9000 в публичную сеть.

### Облачный проект serverist-89be5

Предоставленная RTDB вернула HTTP 423 и ответ `The Firebase database 'serverist-89be5-default-rtdb' has been deactivated.` Профиль может выполнять необязательную диагностику указанного URL при наличии переменных `VITE_WAITER_FIREBASE_PROJECT_ID` и `VITE_WAITER_FIREBASE_DATABASE_URL`. Запись в рабочий облачный проект требует активной RTDB и согласованного доступа. Текущая синхронизация работает через Emulator, исходный режим при пустой переменной Emulator использует локальную IndexedDB. Проект правил облачной базы по умолчанию закрывает чтение и запись в пространстве waiter.

## Сборка и установка PWA

```sh
npm run build
npm run preview -- --port 4173
```

В Chrome, Edge или Android откройте экран установки и используйте кнопку приложения либо меню браузера. На iPhone и iPad в Safari выберите «Поделиться» → «На экран Домой» → «Добавить». Запустите приложение с созданной иконки. В Safari 17+ на macOS для совместимого режима используйте «Добавить в Dock» и запустите приложение из Dock.

Для GitHub Pages содержимое `dist/` размещается внутри `waiter/` в артефакте действующего сайта. Для Do-go это даёт базу `/Do-go/waiter/`. Manifest, иконки, SW и маршруты используют относительные пути. Сборка `npm run build -- --mode demo` позволяет использовать Emulator с установленным PWA, если сервер Emulator достижим в той же доверенной среде. Обычная сборка игнорирует флаг Emulator.

## Проверки

```sh
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm run test:emulator
npm run test:emulator:e2e
```

Если Node SDK отправляет локальный WebSocket через прокси, для `test:emulator` запустите команду с удалёнными `HTTP_PROXY`, `http_proxy`, `HTTPS_PROXY` и `https_proxy` в окружении процесса. Ограничения и проверенные сценарии перечислены в [PROGRESS.md](PROGRESS.md).
