# Архитектура

## Приложение

React и строгий TypeScript. Vite, Tailwind, Motion, Lucide. Zustand хранит текущий снимок рабочего пространства, очередь и состояние связи. Разделы переключаются через URL hash и остаются смонтированы после первого открытия. Академия монтирует то же рабочее пространство с подсветкой и нижней панелью. В режиме обучения команды и сообщения идут в песочницу профиля и сохраняются в IndexedDB. Сертификат после перехода в рабочую смену попадает в демонстрационный реестр с устойчивым ключом.

Vite берёт HTML из src/index.html. Сценарий build:pages подготавливает статический HTML, JS, CSS, иконки и service worker внутри waiter/. GitHub Pages раздаёт эти файлы из уже настроенной ветки. Manifest использует относительные start_url и scope. Workbox кеширует сборку и обслуживает переходы только в scope своего worker. В режиме разработки service worker отсутствует. Production проверяет standalone перед загрузкой профиля и разделов.

## Хранение

| IndexedDB | Назначение |
| --- | --- |
| snapshots | Подтверждённые данные разделены по адаптеру и точке |
| outbox | Операции с ID, очередностью, счётчиком попыток и состоянием отказа |
| messages | Загруженная история с индексом по комнате и времени. До 350 записей на комнату |
| settings | Меню и план, профиль, настройки, прочтение, Академия и сертификат |

Запись команды в outbox предшествует показу результата. Негранулярные снимки из офлайн-кеша никогда не отправляются на сервер. После получения снимка из RTDB команда снова проигрывается только по подтверждённым данным. Черновики, редактирование позиции и комментарии отображаются оптимистично. Открытие стола, изменение стока, подтверждение, статусы и оплата ожидают квитанции. Сетевые ошибки повторяются с задержкой. Бизнес-конфликт остаётся видимым в outbox, пока его не скроют. Таймеры вычисляются по временным меткам без сетевой записи.

## Firebase Emulator

```
coffeemanWaiter/
  workspaces/{branch}/
    revision
    occupied/{table}
    active/{order}
    archived/{order}
    stock/{item}
    receipts/{operation}
    audit/{event}
    config/{dish|table|category}/{id}
  workspaces/registry/config/{staff|branch|training|certificate|preferences}/{id}
  messages/{branch}/{chat}/{message}
  presence/{branch}/{person}/{connection}
```

У заказа сохраняется цена в копейках и версия каждой строки. Команда редактирования сравнивает версию конкретной строки. Разные позиции могут редактироваться независимо. Для атомарного изменения остатков, состояний заказа, занятости и журнала используется runTransaction на узле конкретной точки. Транзакция применяет команду к актуальному снимку. Отправка ветки с клиента при транзакции увеличивает объём передачи с ростом архива и журнала. Перед масштабированием нужно изменить разбиение данных и определить срок хранения квитанций. История действий и квитанции используют serverTimestamp. Строки и таймеры используют часы выполняющего операцию устройства.

Административные правки используют ту же постоянную очередь, транзакции RTDB и отдельную версию на запись справочника. Ветвевые изменения меню и плана применяются к рабочей точке, общие записи читаются через отдельную подписку на registry. Настройки, которые ещё не менялись, наследуют исходные демонстрационные справочники.

Сообщения получают уникальные ID до отправки. Правило создания и проверка существующего сообщения сохраняют исходную запись при повторе. Клиент получает последние 35 сообщений комнаты и отдельные порции истории. Для присутствия каждое подключение использует собственный ключ, .info/connected и onDisconnect. Подписки очищаются при смене профиля или точки.

## Безопасность

Общая база существующих приложений Do-go не используется. Облачная RTDB доступна для диагностики чтения. Рабочая синхронизация в облаке требует подтверждённого доступа и согласованных правил. Правила Emulator существуют отдельно, для вымышленных профилей. Выбор профиля не удостоверяет личность, журнал тестового режима допускает изменение участниками с прямым доступом к Emulator. Установка PWA ограничивает интерфейс. Академия хранит только локальные сценарии и команды песочницы.
